# План реалізації: UML-модель і CRC-картки навчальної системи «Автосервіс»

**Гілка**: `001-auto-service-uml` | **Дата**: 2026-11-11 | **Специфікація**: [spec.md](spec.md)

**Вхідні дані**: Специфікація функції `specs/001-auto-service-uml/spec.md`.

## Короткий опис

Підготувати українською мовою узгоджений комплект проєктної документації для навчальної інформаційної системи «Автосервіс»: діаграму варіантів використання у PlantUML, діаграми класів, послідовності та станів у Mermaid, а також книгу CRC-карток Excel. Модель відображатиме чотири наскрізні сценарії та ролі власника авто, приймальника й механіка. Імена типів і програмних елементів будуть англійською, пояснювальний текст — українською.

## Технічний контекст

**Мова/версія**: Українська для документації; Java-подібна нотація для об'єктно-орієнтованої моделі згідно з Конституцією проєкту.

**Основні залежності**: PlantUML для `docs/usecase.puml`; Mermaid для трьох `*.mmd`; `openpyxl` як локальний інструмент створення/перевірки `docs/crc.xlsx`, не як залежність програми.

**Зберігання**: Файли документації у репозиторії; зовнішнє сховище не потрібне.

**Перевірка**: Локальний синтаксичний рендер PlantUML і Mermaid, перевірка структури XLSX та ручна звірка сценаріїв і моделі між артефактами.

**Цільове середовище**: Локальна робоча копія репозиторію; мережеві сервіси під час виконання моделі не використовуються.

**Тип проєкту**: Документаційне проєктування для навчальної консольної Java-системи. У поточному репозиторії є специфікація, але немає вихідного застосунку.

**Цілі продуктивності**: Не застосовуються; артефакти невеликі та призначені для навчання.

**Обмеження**: Мінімальна складність; жодних серверів, баз даних чи зовнішніх інтеграцій; діаграми мають залишатися узгодженими; у кожного класу — атрибут або метод і конструктор; модель показує інтерфейс, абстрактний клас, наслідування, реалізацію, залежність, композицію/агрегацію, перевизначення, перевантаження та `final`-метод.

**Обсяг**: Чотири діаграми та одна книга CRC-карток; 11 класів (включно з абстрактним) і один інтерфейс; усі основні сценарії з `spec.md`.

## Перевірка Конституції

| Принцип / вимога | Результат |
|---|---|
| Мінімальна складність і SRP | **Відповідає**: окремі сутності та один вузький сервіс запису; без зайвих шарів чи інтеграцій. |
| Консольна локальна модель | **Відповідає**: діаграми описують локальний навчальний процес, а не реальну онлайн-інфраструктуру. |
| Залежності передаються явно | **Відповідає**: взаємодії відображаються явними параметрами операцій/зв'язками, без глобальних об'єктів. |
| Англійські імена, українська документація | **Відповідає**: імена класів та операцій англійські; описи, підписи й CRC-вміст українські. |
| Документація зберігається у `docs/` | **Відповідає**: усі п'ять кінцевих артефактів мають визначені шляхи в `docs/`. |
| Зовнішні залежності | **Відповідає з обмеженням**: `openpyxl` потрібен лише локально для створення/перевірки XLSX, не для запуску системи. Не додається до runtime-залежностей. |

**Результат воріт до проєктування**: критичних порушень немає; етап дослідження дозволено.

## Структура проєкту

### Документація функції

```text
specs/001-auto-service-uml/
├── plan.md              # цей план
├── research.md          # рішення щодо форматів і валідації
├── data-model.md        # типи, атрибути, поведінка та зв'язки
├── quickstart.md        # локальні кроки перевірки артефактів
└── spec.md              # вимоги функції
```

### Кінцеві артефакти

```text
docs/
├── usecase.puml
├── class.mmd
├── sequence.mmd
├── state.mmd
└── crc.xlsx
```

**Рішення щодо структури**: зміни обмежені документаційними файлами. Каталог `contracts/` не створюється: функція не додає зовнішній API або інший системний контракт.

## Ризики й межі

- Mermaid і PlantUML мають різний синтаксис: кожну діаграму слід перевіряти відповідним рендерером, не копіювати нотацію між мовами.
- `docs/crc.xlsx` — бінарний артефакт: потрібно перевірити відкриття книги, заголовки колонок і наявність карток для кожного класу.
- «Онлайн-запис» у сценарії є дією власника в навчальній моделі; це не є вимогою створити вебзастосунок чи мережевий сервіс.
