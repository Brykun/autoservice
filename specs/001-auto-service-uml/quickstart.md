# Перевірка артефактів «Автосервіс»

Цей посібник перевіряє готові файли з кореня репозиторію. Він не запускає застосунок: у цій функції створюється документація, а не реалізація сервісу.

## Передумови

- Локальна копія репозиторію.
- PlantUML для рендерингу `docs/usecase.puml`.
- Mermaid CLI (`mmdc`) для рендерингу файлів `*.mmd`.
- Python 3 та `openpyxl` у локальному середовищі для перевірки книги XLSX.

Ці інструменти потрібні лише для авторської перевірки документів; вони не є runtime-залежностями системи. Необов'язково встановлювати їх у середовище виконання проєкту.

## Синтаксична перевірка діаграм

З кореня репозиторію запустити:

```sh
plantuml -checkonly docs/usecase.puml
mmdc -i docs/class.mmd -o /tmp/autoservice-class.svg
mmdc -i docs/sequence.mmd -o /tmp/autoservice-sequence.svg
mmdc -i docs/state.mmd -o /tmp/autoservice-state.svg
```

**Очікувано**: усі команди завершуються без синтаксичних помилок; Mermaid генерує три SVG-файли у `/tmp`.

## Перевірка книги CRC

```sh
python3 - <<'PY'
from openpyxl import load_workbook

workbook = load_workbook("docs/crc.xlsx", read_only=True, data_only=True)
sheet = workbook.active
rows = list(sheet.iter_rows(values_only=True))
assert rows and "Обов'язки класу" in rows[0] and "З ким співпрацює" in rows[0]
print(f"Аркуш: {sheet.title}; рядків: {len(rows)}")
PY
```

**Очікувано**: книга читається без помилки, перший рядок містить обидва обов'язкові заголовки, аркуш має рядки карток.

## Наскрізна звірка

1. Переконатися, що в PlantUML показані актори Власник авто, Приймальник і Механік та всі чотири сценарії зі специфікації.
2. Звірити назви типів, операцій і відносин у Mermaid-діаграмі класів із [моделлю даних](data-model.md); переконатися, що видно абстрактний клас, інтерфейс, наслідування, реалізацію, залежність, композицію/агрегацію, `final`, перевизначений і перевантажений методи.
3. Переконатися, що діаграма послідовності відображає той самий порядок взаємодій: запис → приймання та кошторис → рішення щодо додаткових робіт → виконання й облік запчастин → завершення.
4. Переконатися, що діаграма станів має початковий і кінцеві стани та відображає погодження/відмову, виконання, скасування й завершення.
5. Перевірити, що CRC-картки охоплюють усі класи з діаграми класів та містять їхні обов'язки й співпрацівників.

**Очікувано**: п'ять артефактів описують один сервісний цикл без суперечностей; картка інтерфейсу може бути включена як додаткова, але не замінює картки класів.
